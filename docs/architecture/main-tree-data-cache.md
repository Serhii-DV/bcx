# Main tree subtree caching (`TreeItemCache`)

## Current implementation summary

The extension no longer caches the whole `MainTreeData` object. Instead, it caches individual subtree `TreeItem`s through `TreeItemCache`.

Location:
- `src/app/treeview/items/TreeItemCache.ts`
- consumed by `src/app/treeview/items/MainTreeData.ts`

## Why subtree cache instead of whole-tree cache

`MainTreeData.create(...)` composes multiple sections with different volatility:
- release / band details
- following bands / following genres
- collection / wishlist
- history

Caching each subtree separately improves freshness control and avoids invalidating the entire tree when only one section changes.

## Cache layers

`TreeItemCache` uses two layers:

1. **Memory cache** (`Map`) for fastest hits in the same runtime.
2. **Session storage cache** (`chrome.storage.session`) for warm recovery.

Both layers store serialized `TreeItem` snapshots with:
- `createdAt`
- `expiresAt`
- `version`
- serialized `item`

## Keying

Keys are generated by `TreeItemCache.subtreeKey(...)` under prefix:

```text
/ui/main-tree-subtree-cache/...segments
```

Current subtree key segments include:
- `release/{albumId}/{urlUuid}`
- `band/{bandId}/{urlUuid}`
- `following-bands/{fanKeyPart}`
- `following-genres/{fanKeyPart}`
- `collection/{fanKeyPart}`
- `wishlist/{fanKeyPart}`
- `history/{historyKeyPart}`

Where:
- `fanKeyPart = username || fan_id || 'anonymous'`
- `historyKeyPart = username || fan_id || 'anonymous'`

## TTL strategy (current)

Configured in `MainTreeData.create(...)`:

- release: 24h
- band: 24h
- following bands: 60m
- following genres: 60m
- collection: 30m
- wishlist: 30m
- history: 10m

## Serialization notes

To support storage serialization:
- runtime handlers are not persisted
- button entries are persisted only for link-style metadata (`title`, `href`)
- icon constructors are mapped via stable keys (currently `external-link`, `funnel`) and rehydrated on load

## Invalidation

Explicit loader actions call `TreeItemCache.invalidateAll()` (via `createLoadHandler`) to clear both memory and session layers.

## Observability

Cache reads log timing and hit/miss information:
- `TreeItemCache.get:<key>`
- includes cache layer (`memory` or `session`) on hits
